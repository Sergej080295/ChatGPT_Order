# Запуск Planner Codex v3 на локальном сервере

Ниже описаны все шаги, начиная с создания папки и копирования исходных файлов, до проверки работы сервера.

## 1. Подготовка каталога проекта
1. Создайте новую папку, например `C:\planner-codex` (или любой другой путь).
2. Скопируйте в неё файлы из архива/репозитория:
   - `server.js`
   - `package.json`
   - `package-lock.json`
   - `planner-state.json`
   - `.gitignore`
   - каталог `public` целиком (внутри него находится `Planner_Codex_v3.html`).

> 💡 Файл `Planner_Codex_v3.html` — единственная актуальная версия планировщика. Все старые файлы можно удалить, чтобы избежать путаницы.

## 2. Установка Node.js
1. Скачайте LTS-версию Node.js с [https://nodejs.org/](https://nodejs.org/).
2. Установите Node.js, следуя подсказкам мастера установки.
3. Откройте PowerShell или терминал и убедитесь, что Node установлен:
   ```powershell
   node -v
   npm -v
   ```
   Обе команды должны вывести номер версии.

## 3. Установка зависимостей
1. В терминале перейдите в каталог проекта, например:
   ```powershell
   cd "C:\planner-codex"
   ```
2. Установите зависимости (Express уже указан в `package.json`):
   ```powershell
   npm install
   ```
   После выполнения команды появится папка `node_modules` и файл `package-lock.json` (если его не было).

## 4. Запуск сервера
1. Всё ещё находясь в каталоге проекта, запустите сервер:
   ```powershell
   npm start
   ```
2. В терминале появится сообщение вида `Planner server running on http://localhost:3000`.
   Пока окно PowerShell открыто, сервер работает.

## 5. Проверка работы
1. Откройте браузер и перейдите по адресу [http://127.0.0.1:3000/Planner_Codex_v3.html](http://127.0.0.1:3000/Planner_Codex_v3.html).
2. В правом верхнем углу интерфейса должен отображаться статус соединения с базой (онлайн/оффлайн).
3. Любые изменения с включённым AutoSave будут моментально сохраняться в файл `planner-state.json` и транслироваться на другие открытые сеансы через SSE-канал `/api/events`.

## 6. Ручное сохранение (если AutoSave отключён)
- Нажмите кнопку «Сохранить» в интерфейсе планировщика. Сервер получит обновлённое состояние и запишет его в `planner-state.json`.

## 7. Журналы и диагностика
- Каждый успешный запрос сохранения дописывает запись в `planner-activity.log` (файл создаётся автоматически и игнорируется Git).
- При конфликте версий сервер вернёт ошибку `409 Conflict` и уведомит, кто последний изменял данные.

## 8. Остановка сервера
- В терминале с запущенным сервером нажмите `Ctrl + C`.

## 9. Типичные проблемы
- **Порт 3000 занят** — завершите другой процесс на этом порту или измените `PORT` через переменную окружения перед запуском (`set PORT=4000`, затем `npm start`).
- **Нет синхронизации** — убедитесь, что все браузеры открывают `Planner_Codex_v3.html` с одного и того же сервера и что файл `planner-state.json` доступен для записи.

Следуя этим шагам, вы получите единый актуальный планировщик (версия v3), работающий поверх Node.js/Express, с сохранением в `planner-state.json` и автоматическим обменом данными между всеми подключёнными клиентами.
