## Дополнительное исправление после v5.7

Проблема:

- в списке вместимостей отображался передел «Рубка», хотя он не добавлен пользователем;
- при обновлении страницы некоторые значения вместимости временно сбрасывались и позже восстанавливались.

Сделано:

- список «Вместимость» строится только по активным часовым переделам из «Списка переделов»;
- список «Параллельные операции» строится только по активным безчасовым переделам;
- `capacity` и `parallel` сохраняются в sparse-режиме без автоматического заполнения всеми дефолтными ключами;
- сохранение формы настроек записывает значения только для текущих отображаемых переделов.

## v5.7.1

Проблема:

- несколько реально созданных пользователем часовых переделов могли схлопываться в один внутренний ключ и из-за этого не отображаться отдельными строками во «Вместимости»;
- при открытии настроек сразу после обновления страницы могли быть видны временные значения `1`, пока remote snapshot ещё не применился поверх локального состояния;
- изменения, сделанные во время уже идущей синхронизации или при конфликте snapshot, могли не уйти на сервер с первой попытки.

Сделано:

- видимые пользовательские переделы получают отдельный стабильный custom-key, если fixed-key уже занят другим переделом;
- remote snapshot больше не смешивается со stale-настройками из localStorage;
- сохранение CRM накладывает локальные изменения на свежий серверный snapshot, чтобы не терять чужие параллельные изменения;
- очередь синхронизации повторно запускается, если новая правка появилась во время активного сохранения;
- версия UI обновлена до `5.7.1`.

## v5.7.2

Проблема:

- общие выходные и праздники не применялись к переделам после сохранения календаря;
- дополнительные смены по переделу не давали рабочий день в расписании;
- в интерфейсе редактирования пользователя не было понятно, сохранится ли текущий пароль;
- журналы не позволяли быстро отфильтровать конкретный тип событий.

Сделано:

- глобальный календарь `__global__` сохраняется при санитарной обработке календарей переделов;
- дополнительные смены учитываются в расчете графика и визуально отмечаются в стековом и Gantt-представлениях;
- список пользователей отдает признак наличия пароля и дату его обновления, а форма редактирования явно показывает, что пустое поле не меняет текущий пароль;
- добавлены фильтры типов записей в журнал изменений CRM и журнал действий администрирования;
- версия UI обновлена до `5.7.2`.

## v5.7.3

Проблема:

- добавление общих выходных и дополнительных смен оставалось локальным черновиком формы и могло не попадать в видимый список сразу после нажатия `Добавить`;
- при замене передела в заказе старые служебные поля исходного передела могли переноситься в новый передел, из-за чего данные были видны в заказе, но не распределялись по странице передела, Ганту и общему маршруту;
- при смене часового передела на безчасовой в редакторе заказа визуально оставалась старая ячейка часов;
- удаление передела из каталога не требовало подтверждения;
- на странице заказов отображались две горизонтальные прокрутки;
- в админке не было настройки времени выхода пользователей из системы.

Сделано:

- общие выходные и дополнительные смены сохраняются сразу после добавления или удаления и сразу остаются видимыми в списках;
- при смене типа передела строка в заказе пересобирается под новый тип, а часы очищаются при переходе на безчасовой передел;
- служебные ключи, метаданные графика и старые часы исходного передела больше не переносятся при замене передела в существующем заказе;
- добавлено подтверждение удаления передела из списка переделов;
- нижние плитки общего маршрута используют пользовательский цвет передела из настроек;
- строка итогов на странице заказов больше не показывает отдельный горизонтальный скроллбар;
- в настройках администрирования добавлены таймаут бездействия и плановый выход из системы, сервер применяет их к текущим сессиям;
- форма редактирования пользователя показывает статус текущего пароля и поясняет, что пароль хранится как защищенный хэш; смена пароля остается через кнопку с ключом;
- версия UI обновлена до `5.7.3`.

## v5.7.4

Проблема:

- релизный архив мог содержать локальные скрипты запуска, которые мешали развертыванию у заказчика;
- требование к Node.js было указано как `>=18`, хотя текущая версия `better-sqlite3` требует Node.js 20 или новее.

Сделано:

- релизный архив собирается только из переносимого набора файлов без `node_modules`, `.git`, документации, локальных bat/ps1-скриптов, `server.pid`, логов и рабочих файлов `data/`;
- архив нормализуется под LF-переносы строк и содержит явные записи папок, как в старом рабочем архиве;
- минимальная версия Node.js уточнена до `>=20`;
- версия UI обновлена до `5.7.4`.

## v5.7.5

Проблема:

- пользовательские роли и права на пользовательские переделы могли работать некорректно после перезапуска сервера;
- часть действий в интерфейсе проверяла только общее право на переделы и не учитывала доступ роли к конкретному переделу;
- пользователь с правом `manageSettings`, но без `manageUsers`, не мог полноценно работать с вкладкой настроек администрирования;
- страница входа показывала устаревшую версию из общего скрипта.

Сделано:

- сервер теперь сохраняет и восстанавливает кастомные роли и динамические ключи `stageAccess`;
- клиент больше не отбрасывает права на пользовательские переделы при загрузке текущего пользователя и при пересохранении ролей;
- кнопки, строки заказа, даты, прогресс, удаление, перемещение, бронь и оптимизация проверяют доступ к конкретному переделу;
- вкладка настроек администрирования доступна по праву `manageSettings`, без требования `manageUsers`;
- добавлены интеграционные проверки ролей до и после перезапуска сервера;
- версия UI обновлена до `5.7.5`.

## v5.7.6

Проблема:

- после добавления пользовательских переделов в настройках ролей галочки могли выглядеть включенными, но текущая сессия пользователя не получала доступ к этим новым ключам переделов;
- строка заказа могла проверять доступ по одному распознанному ключу, хотя в роли право сохранено под ключом базового пресета или названием передела.

Сделано:

- права текущего пользователя по переделам синхронизируются с актуальным динамическим каталогом переделов перед проверкой доступа;
- проверка доступа к переделу теперь учитывает ключ, название, базовый передел и алиасы, чтобы пользовательские/многошаговые переделы не блокировались ошибочно;
- версия UI обновлена до `5.7.6`.

## Текущие зоны повышенного риска

1. Слияние remote snapshot, localStorage fallback и sparse-настроек.
2. Старые данные с переделами/этапами, которых нет в новых настройках.
3. Бронь и замороженные сегменты расписания.
4. Права на конкретные переделы после динамического каталога.
5. Общий Гант: прокрутка, поиск, клики по заказам.
6. Корзина и восстановление заказов.
7. Ошибки записи в `data/` и корректность сообщений пользователю.
