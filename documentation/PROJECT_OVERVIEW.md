# Обзор проекта Планировщика

## Назначение

Планировщик / PlanCore CRM — веб-приложение для ведения заказов и планирования производственных переделов. Приложение объединяет:

- CRM-доску заказов по статусным колонкам;
- карточку заказа с деталями, составом, этапами и комментариями;
- страницы отдельных переделов;
- общую и детальную диаграмму Ганта;
- маршрут заказа по переделам;
- настройки производственных переделов, этапов, вместимости, календарей, прав и отображения;
- административную панель пользователей, ролей и аудита.

## Основные сущности

### Доска

Доска содержит список колонок и заказов. Колонки по умолчанию отражают движение заказа от незапланированного состояния до отгрузки. Текущая доска хранится в `currentBoardId`.

### Заказ

Заказ — основная бизнес-сущность. В заказе обычно есть:

- номер/название;
- дата;
- клиент/контактные данные;
- статусная колонка;
- состав заказа: детали, остатки, доли;
- список переделов/этапов;
- комментарии и журнал изменений;
- признаки готовности, даты начала/окончания, прогресс.

### Передел

Передел — производственная операция. В приложении есть фиксированные внутренние ключи (`draw`, `laser`, `bend`, `weld` и др.) и пользовательский «Список переделов», который может создавать динамические ключи для новых операций.

Передел бывает двух типов:

- **часовой** — планируется по трудоемкости и дневной вместимости;
- **безчасовой** — планируется как индикатор/параллельная операция с лимитом одновременных заказов.

### Этап передела

Этап — уточнение внутри передела. После удаления старого раздела сопоставления данных этапы задаются вручную в «Списке переделов». Для старых заказов предусмотрена диагностика конфликтов, если в заказах встречаются этапы, которых нет в настройках.

### Вместимость

Вместимость — количество часов в день для часового передела. Она влияет на расчет расписания и Ганта. Важно: в списке вместимостей должны быть только реально созданные пользователем часовые переделы.

### Параллельные операции

Параллельность — лимит одновременных заказов для безчасовых переделов. Это не часы, а количество параллельных позиций.

### Бронь и исключения календаря

Для переделов есть календарь:

- **исключения** — дни без доступной мощности или с особым значением;
- **бронь** — зарезервированная мощность;
- **глобальные исключения** — общие выходные, применяемые ко всем релевантным календарям.

Нулевые и пустые исключения считаются валидными для сценария «выходной/исключение».

## Основные пользовательские разделы

- **CRM** — канбан-доска с заказами.
- **Заказы** — табличный список заказов и итоговые значения.
- **Страница передела** — список заказов конкретного передела, готовность, бронь, локальный Гант.
- **Гант** — общая диаграмма по всем переделам.
- **Маршрут** — представление прохождения заказов по переделам.
- **Настройки** — доска, переделы, этапы, вместимость, параллельность, автооптимизация, экспорт/импорт, конфликты данных.
- **Админка** — пользователи, роли, права и аудит.

## Ключевые бизнес-правила

1. Переделы в настройках являются источником истины для списков вместимости и параллельных операций.
2. Заказы со старыми переделами/этапами не должны ломать интерфейс: такие данные должны диагностироваться через «Конфликты данных».
3. Автодаты используют настраиваемый сдвиг старта, по умолчанию `+1` день.
4. Нулевые исключения календаря сохраняются как рабочий сценарий, а не отбрасываются.
5. Бронь не должна увеличивать фактическую дневную вместимость сверх заданных лимитов.
6. При смене типа передела «часовой/безчасовой» нужно проверять связанные значения вместимости/параллельности, Гант и готовность.
7. Права пользователя должны проверяться и на сервере, и в UI: видимость кнопок не заменяет серверную авторизацию.
