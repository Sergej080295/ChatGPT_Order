# QA, диагностика и поиск ошибок

## Минимальный smoke-test после любых изменений

1. `node --check server.js`.
2. `node --check public/plan-core.js`.
3. Проверить синтаксис скрипта из `public/CRM.html` через `new Function`.
4. `git diff --check`.
5. Запустить сервер и проверить `curl -I http://localhost:3000/CRM.html`.
6. В браузере: войти, открыть CRM, настройки, список заказов, страницу передела и общий Гант.

## Обязательные ручные сценарии

### Заказы

- Создать заказ.
- Изменить заказ.
- Переместить заказ между колонками.
- Добавить/удалить передел в заказе.
- Отметить готовность передела галочкой.
- Удалить заказ и восстановить из корзины.
- Проверить итоговые строки в «Заказы» и на странице передела.

### Переделы и настройки

- Добавить новый часовой передел.
- Убедиться, что он появился во «Вместимости».
- Изменить вместимость, сохранить, обновить страницу, проверить что значение не сбросилось.
- Добавить безчасовой передел и проверить «Параллельные операции».
- Удалить передел и проверить, что он исчез из связанных UI.
- Открыть «Конфликты данных» и проверить список старых ссылок.

### Гант

- Открыть Гант конкретного передела.
- Открыть общий Гант.
- Проверить колонку «Заказ / Дата».
- Проверить горизонтальную прокрутку.
- Нажать на название заказа.
- Проверить поиск по заказам.

### Бронь и календарь

- Добавить исключение с пустым значением.
- Добавить исключение со значением `0`.
- Добавить бронь.
- Проверить, что суммарная нагрузка не превысила вместимость.
- Проверить Гант после брони.

### Права

- Проверить пользователя с полными правами.
- Проверить мастера участка.
- Проверить гостя.
- Проверить выдачу прав на конкретные переделы.
- Проверить, что UI скрывает недоступные действия и сервер также запрещает их.

## Частые симптомы и причины

### В списке вместимостей виден передел, которого нет в «Списке переделов»

Вероятная причина: настройки были нормализованы с дефолтными ключами или сохранились старые ключи. Список UI должен строиться только из активных часовых пользовательских переделов.

Где смотреть:

- `getCrmCapacityStageKeysForSettings()`;
- `normalizeCapacityMap()`;
- submit обработчик формы настроек;
- окно «Конфликты данных».

### Вместимость сбрасывается после обновления страницы

Проверить:

1. Есть ли `412 Conflict` в Network.
2. Есть ли `507 StoragePermission`.
3. Не применяется ли localStorage поверх remote snapshot.
4. Не заполняет ли sanitizer отсутствующие ключи дефолтами.
5. Есть ли несколько вкладок с разными ревизиями.
6. Что реально лежит в последнем snapshot SQLite.

SQL-проверка:

```bash
sqlite3 data/planner.db "SELECT rev, saved_at, substr(state_json,1,200) FROM snapshots ORDER BY rev DESC LIMIT 3;"
```

### Заказ не сохраняется

Проверить:

- авторизован ли пользователь;
- есть ли права `write` и действие (`createOrders`/`editOrders`);
- ответ `PUT /api/state`;
- writable ли `data/`;
- не истекла ли сессия;
- нет ли конфликтов snapshot hash.

### Не работает галочка готовности передела

Проверить:

- event handler чекбокса;
- право `updateStageProgress`;
- доступ `stageAccess` к конкретному переделу;
- пересчет статуса заказа;
- save reason в `save()`;
- отсутствие JS-ошибки в консоли.

### Бронь распределяет слишком много часов

Проверить:

- дневную вместимость передела;
- `resLim`, `resUsed`, `pubCap`, `pubUsed` в рассчитанном расписании;
- замороженные сегменты;
- исключения календаря;
- нет ли искусственного `Math.max(originalCap, used)` в коде расчета.

### Гант съехал или строки переносятся

Проверить:

- ширину колонки «Заказ / Дата»;
- CSS `white-space`, `overflow`, `text-overflow`;
- одинаковую высоту строк слева и в сетке;
- синхронизацию scrollLeft/scrollTop;
- общий Гант и Гант страницы передела отдельно.

## Как безопасно менять функции

1. Найти функцию и все вызовы: `rg -n "имяФункции" public server.js`.
2. Проверить связанные sanitizer/renderer/save-flow.
3. Изменить минимально возможную область.
4. Запустить синтаксические проверки.
5. Пройти ручной сценарий по затронутым разделам.
6. Если меняется состояние данных, проверить старый snapshot и импорт.
7. Обновить документацию и историю версий.

## Набор команд для расследования

```bash
# поиск функции или DOM id
rg -n "crmSettingsConflicts|capacity|parallel|stagePresets" public/CRM.html server.js

# последние коммиты
git log --oneline -10

# отличия последнего коммита
git show --stat --oneline HEAD

# проверка состояния git
git status --short

# проверка runtime логов при запуске
node server.js
```

## Что нельзя делать без дополнительной проверки

- Удалять старые поля состояния без миграции.
- Менять внутренние ключи переделов без обновления mapping и stageAccess.
- Заполнять sparse-настройки дефолтами при сохранении.
- Молча игнорировать `412` и `507`.
- Исправлять UI-кнопку без проверки серверного права.
- Изменять календарь переделов без проверки нулевых исключений и брони.
