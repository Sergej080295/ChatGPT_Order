# Поток данных заказов по переделам

Обновлённый PlanCore не использует промежуточные «снимки». Все действия пользователя сразу отражаются в таблицах `pc_orders` и `pc_order_tasks`, а затем отображаются в CRM и в Планировщике.

## 1. Откуда берутся данные для колонок переделов
1. Клиент вызывает `GET /api/stages`.
2. Сервер:
   * Загружает каталог стадий из встроенного справочника.
   * Выполняет `SELECT` из `pc_order_tasks`, группируя строки по `stage_code`.
   * Для каждой карточки подмешивает информацию о заказе (`SELECT ... FROM pc_orders WHERE id = order_id`).
3. Ответ содержит объект `{ stages: { [stage_code]: [...] }, catalog: [...] }`, где каждая карточка включает поля заказа, прогресс, сроки и исполнителя.

## 2. Как изменения пользователя попадают в таблицы
### 2.1 Заказы
* При создании/редактировании заказа CRM вызывает `POST /api/orders` или `PATCH /api/orders/:id`.
* Сервер формирует `INSERT/UPDATE` в `pc_orders` и записывает событие в `pc_journal`.

### 2.2 Переделы
* В Планировщике карточка передела изменяется через `PATCH /api/stages/:stageId`.
* Сервер обновляет соответствующую строку в `pc_order_tasks` (готовность, сроки, статус) и добавляет запись `stage.updated` в журнал.
* Быстрое завершение этапа (`Готово`) — это тот же `PATCH` с `ready_percent=100` и текущим `actual_finish`.

### 2.3 Добавление/удаление этапов
* `POST /api/orders/:id/stages` создаёт новую строку в `pc_order_tasks` с позициями, вычисленными на клиенте.
* `DELETE /api/stages/:stageId` удаляет передел и фиксирует событие `stage.deleted`.

## 3. Как данные попадают обратно в интерфейс
1. После любого изменения приложение выполняет повторный `GET /api/stages` или `GET /api/orders`.
2. Полученные массивы карточек/этапов записываются в локальное состояние и рендерятся в колонках.
3. Поскольку CRM и Планировщик используют одни и те же запросы, изменение статуса передела мгновенно видно и в доске CRM.

## 4. Минимальный сценарий проверки
1. Создайте заказ в CRM: `+ Заказ → сохранить`. В таблице `pc_orders` появится строка с новым `id`.
2. Откройте Планировщик, добавьте передел «Лазер». В таблицу `pc_order_tasks` добавится строка с `stage_code = 'laser'`.
3. Отметьте готовность передела на 50 %. Команда `SELECT ready_percent FROM pc_order_tasks WHERE stage_code='laser';` покажет обновлённое значение.
4. Обновите страницу Планировщика — карточка сразу отобразит новый прогресс без дополнительных действий.

Таким образом, цепочка «CRM → SQL → Планировщик» теперь линейная и не зависит от восстановления/нормализации снимков.
