
# 📋 Техническое задание: Надёжное хранение и применение настроек (через «Применить»)

## 🎯 Цель
Устранить «слёты» настроек и сделать их стабильно сохраняемыми **только** по кнопке **«Применить»**:

- Автодовес (параметры);
- Кол-во записей в журнале;
- Сопоставление данных (CRM → этап Планировщика);
- Ширина колонок «Список заказов» (px, единый набор на все переделы).

Настройки должны быть отделены от «большого состояния» Планировщика, исключая перезапись через SSE/PUT `/api/state`.

---

## ⚙️ Архитектурные изменения

### 1) Отдельное хранилище настроек в БД

Создать таблицу `planner_settings` (глобальные настройки):

| Поле | Тип | Описание |
|------|-----|-----------|
| id | BIGSERIAL PK |  |
| key | TEXT UNIQUE | Ключ настройки (`autoweight`, `journal.maxRows`, `mapping.rules`, `columns.widths`) |
| value | JSONB NOT NULL | Данные настройки |
| version | INTEGER DEFAULT 1 | Инкремент при каждом изменении |
| updated_at | TIMESTAMPTZ DEFAULT NOW() | Дата обновления |

> В будущем можно добавить `planner_user_settings` с `user_id` для персональных параметров.

---

### 2) Разделить каналы синхронизации

- Состояние планировщика остаётся через `/api/state` и текущий SSE.
- Настройки — через отдельные эндпоинты и SSE:

| Метод | Путь | Описание |
|--------|------|-----------|
| GET | `/api/settings` | Получить все настройки и версии |
| PUT | `/api/settings` | Применить изменения (по кнопке «Применить») |
| GET | `/api/settings/events` | SSE поток изменений настроек |

Настройки больше **не участвуют** в `/api/state`.

---

### 3) Исключить настройки из общего state

- Клиент **не отправляет** и **не читает** `meta.settings` через `/api/state`.
- Сервер игнорирует любые `meta.settings`, пришедшие в `/api/state`.

---

## 📡 Контракты API

### `GET /api/settings`
Возвращает текущие значения и версии:

```json
{
  "settings": {
    "autoweight": {"enabled": true, "params": {"percent": 10, "minimumHours": 2}},
    "journal.maxRows": 500,
    "mapping.rules": [{"crmStage":"Покупка чего-либо","plannerStage":"Закупка"}],
    "columns.widths": {"default":{"num":80,"order":260,"client":200,"start":140,"end":140,"progress":120}}
  },
  "versions": {
    "autoweight": 3,
    "journal.maxRows": 2,
    "mapping.rules": 7,
    "columns.widths": 5
  }
}
```

### `PUT /api/settings`
Пример запроса:
```json
{
  "changes": {
    "journal.maxRows": 1000,
    "columns.widths": {"default":{"num":80,"order":280,"client":220,"start":140,"end":140,"progress":120}}
  },
  "versions": {
    "journal.maxRows": 2,
    "columns.widths": 5
  }
}
```

Правила:
- Применение атомарно в транзакции.
- Проверка `version` по каждому ключу:
  - Если версии совпадают → применяем;
  - Если два пользователя отправили одновременно → возвращаем **409 Conflict** с текстом:
    > «Настройки изменены другим пользователем. Повторите действие позже.»
- Возврат — обновлённые значения и версии.

### `GET /api/settings/events` (SSE)
Отправляет события вида:
```json
{ "key": "columns.widths", "value": {...}, "version": 6, "updated_at": "2025-10-08T12:00:00Z" }
```

## 🧩 Клиент (Planner/CRM)

### Панель «Настройки»

- При открытии — грузим `GET /api/settings`.
- Все изменения 4 блоков пишутся **в локальный буфер**.
- **«Применить»** — один `PUT /api/settings`, ждём OK → очищаем буфер.  
  При 409 — показываем сообщение, буфер остаётся.
- **«Отмена»** — откат буфера к серверным значениям.
- SSE `/api/settings/events` — обновляет значения, если они не редактируются в данный момент.

### Подсветки и UX

- Кнопка «Настройки» подсвечивается, если появились новые CRM-стадии без сопоставления.
- Новые стадии в списке подсвечены «Новое».
- В выпадающем списке добавлен вариант **«Игнорировать»**.
- Подсказка: *«Изменения сохраняются по кнопке «Применить»»*.

### Применение настроек

- **Ширина колонок** — из `columns.widths.default`. Применяется при загрузке и после «Применить».
- **Сопоставление данных** — из `mapping.rules`; новые стадии подсвечиваются, можно выбрать «Игнорировать».
- **Автодовес / Журнал** — из `/api/settings`, только по «Применить».

---

## 🔄 Миграция

1. При первом запуске:
   - Прочитать `state.meta.settings` (если есть) и записать в `planner_settings`.
   - Удалить/игнорировать `meta.settings` в дальнейшем.
2. Клиент: удалить любую сериализацию `meta.settings` из запросов `/api/state`.

---

## ⚔️ Обработка конфликтов

- Пока нет ролей: приоритет — «кто последний применил».
- Если сервер видит одновременное применение — возвращает **409** с сообщением выше.

## 🧱 Форматы значений

| Ключ | Формат |
|------|--------|
| `autoweight` | `{"enabled": true, "params": {"percent": 10, "minimumHours": 2}}` |
| `journal.maxRows` | Число (100–10000, дефолт 500) |
| `mapping.rules` | `[{"crmStage":"Покупка","plannerStage":"Закупка"}, {"crmStage":"Внешняя","plannerStage":"Игнорировать"}]` |
| `columns.widths` | `{"default":{"num":80,"order":260,"client":200,"start":140,"end":140,"progress":120}}` |

---

## 🖥️ Серверная реализация

- Создать таблицу `planner_settings` (DDL).
- Репозиторий:
  - `getAll()`: вернуть map и версии;
  - `updateBatch(changes, versions)`: транзакция с инкрементом версий.
- SSE `/api/settings/events`: отправлять события для изменённых ключей.
- `/api/state`: полностью исключить `meta.settings`.

## ✅ Приёмочные тесты

| № | Проверка | Ожидаемый результат |
|---|-----------|----------------------|
| 1 | Изменить ширины и нажать «Применить» | Сохранилось; одинаково на всех переделах; перезагрузка — без откатов |
| 2 | Изменить параметры Автодовеса | После «Применить» сохранено, пересчёт корректен |
| 3 | Изменить лимит журнала | После «Применить» лимит применён, не сбрасывается |
| 4 | Новые CRM-стадии | Подсветка кнопки, пометка «Новое», опция «Игнорировать» |
| 5 | Конфликт двух пользователей | Оба видят сообщение о конфликте; данные не ломаются |
| 6 | SSE / обновления | Входящие данные не затирают редактируемые значения |

## ⚠️ Примечания
- Глобальные настройки применяются ко всем пользователям.
- Настройки отделены от графика заказов, обновления через SSE теперь независимы.
- Будущая поддержка ролей и пользовательских настроек не ломает новую схему.
